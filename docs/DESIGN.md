# UI/UX 디자인 계약

## 제품 경험

첫 사용자는 복잡한 규칙 편집보다 자소 분리 문제 해결을 먼저 이해할 수 있어야 한다. 고급 사용자는 같은 앱에서 일괄 변경·프리셋·CSV·메타데이터·감시로 확장할 수 있어야 한다. 안전 상태와 실제 mutation 확인은 화면 단순화를 위해 숨기지 않는다.

주 방향은 Native · Quiet · Utility다. 제품 시그니처는 다음 네 가지다.

- 자소 분리 해결을 첫 화면에서 짧은 흐름으로 끝낸다. 처음 보는 사용자가 5초 안에 다음 행동을 알 수 있어야 한다.
- 실제 변경 전 현재 이름과 변경 후 이름, 제외/충돌 이유를 항상 확인할 수 있다.
- 일괄 변경은 일상 작업을 먼저 고르게 하고 고급 규칙은 펼쳤을 때만 보여 인지 부하를 낮춘다.
- 기록/Undo/Recovery는 성공 메시지보다 실제 파일 상태와 확인 가능성을 우선한다.

## 정보 구조

sidebar는 두 부분이다.

- 왼쪽 끝 아이콘 레일: 자소 분리 해결, 파일 이름 일괄 변경, 폴더 자동 감시, 복사한 글자 변환, 그리고 아래쪽에 작업 기록·설정·도움말. 글자 없이 아이콘만 두고 tooltip(이름 — 한 줄 설명)과 접근성 이름을 제공한다. 현재 화면은 강조 표시한다.
- 그 옆 패널: 추가한 파일·폴더의 트리. 맨 위 ‘전체 보기’, 그 아래 추가한 항목과 하위 폴더. 폴더 옆 숫자는 그 안의 변경 가능한 항목 수다. 폴더를 누르면 목록이 그 안의 항목으로 좁혀지고 다시 누르면 풀린다. 추가한 항목은 context menu로 목록에서 제거하고, 패널 제목 옆 메뉴에 하위 폴더 검사 여부와 모두 제거가 있다. 아무것도 추가하지 않았을 때는 짧은 안내만 보인다.

sidebar 접기 버튼은 없다. title bar band의 창 버튼 옆에 앱 이름 NameFix를 표시한다. 창이 좁아지면 sidebar가 자동으로 숨고, 그동안에는 목록 위에 ‘추가한 파일·폴더 N개’ 펼침 줄이 대신 나온다.

상단 band(toolbar)는 비워 두지 않는다. 현재 화면 이름을 창 제목으로 보여 주고, 무언가 추가된 뒤에만 결과 저장·다시 검사·추가 버튼이 나타난다. 작업 기록·설정·도움말은 레일과 메뉴 막대에 있으므로 toolbar에 중복하지 않는다.

유료 등급이 없으므로 Pro badge나 ‘· Pro’ 표기는 쓰지 않는다.

메뉴 막대는 macOS 표준 구성(앱·파일·편집·보기·윈도우·도움말)을 따른다. 보기 메뉴의 ⌘1/⌘2가 두 파일 작업 화면을 전환하고, 윈도우 닫기·최소화·가리기·전체 화면은 시스템 표준 단축키를 쓴다. 결과를 CSV로 저장(⇧⌘E)과 최근 작업 되돌리기는 파일 메뉴, 글자 저장 형식 안내와 진단 보고서는 도움말 메뉴에 둔다. 메뉴·메뉴바 명령은 확인/결과 시트나 실행 중인 mutation 위에 다른 시트를 겹쳐 열지 않는다.

sidebar는 macOS 창 장식/traffic lights와 자연스럽게 이어진다. 가짜 traffic light나 웹 대시보드형 중첩 카드로 대체하지 않는다.

## 상태별 노출 (Progressive Disclosure)

화면은 현재 상태에 필요한 control만 보여 준다. 기능을 지우지 않고 처음 보이는 시점만 늦춘다.

- 입력 없음: 가운데 빈 상태가 유일한 입력 화면이다. 제목, “여기에 놓으세요”, 파일 내용을 바꾸지 않는다는 안내, 파일 선택·폴더 선택, 하위 폴더 검사 여부만 둔다. 통계·검색·필터·정렬·선택·실행 버튼은 없다. 최근 폴더는 사용자가 기억하도록 켠 경우에만 보인다.
- 검사 중: 진행 상황과 취소.
- 결과: 평평한 요약 한 줄(정리할 이름·충돌·선택, 충돌이 있으면 번호 제안 버튼), 검색과 ‘필터·정렬’ 메뉴 하나, 결과 목록, 선택 메뉴, 그리고 화면의 유일한 primary 버튼. 다시 검사·추가·결과 저장은 상단 band에 있다. 목록 아래에 잡다한 동작을 모은 메뉴는 두지 않고, 각 동작은 쓰이는 자리(항목 context menu, 충돌 요약 옆, 메뉴 막대)에 둔다.
- 완료: 결과 시트에서 작업 기록과 되돌리기.

요약 항목은 그 자체가 해당 항목만 보는 필터다. 충돌은 있을 때만 보인다. 전체 개수는 요약이 아니라 “전체 N개 중 M개 표시” 보조 문구로 둔다. 큰 gradient 통계 카드, full-width 입력 버튼, 카드 안의 카드는 쓰지 않는다. 입력 UI는 빈 상태의 한 곳이며 결과 화면에서는 상단 band의 ‘추가’ 메뉴로 줄어든다. drag & drop은 모든 상태에서 창 전체가 받는다.

## 자소 분리 해결

입력 → 검사/변경 결과 확인 → 선택한 이름 합치기 → 최종 확인 순서다. 분리 저장된 글자를 항상 하나로 합치며(NFC) 사용자가 형식을 고를 필요가 없다. 분리 형식이 필요한 드문 경우는 일괄 변경의 고급 규칙에서 바꾼다. 일괄 변경의 초안을 몰래 실행하지 않는다.

최종 확인 시트는 바뀌는 개수, 제외 개수, 숨은 선택, 되돌리기 가능 여부, 항목별 현재 이름 → 변경 후 이름을 보여 준다. 버튼은 macOS 관례대로 취소가 왼쪽, 실행이 오른쪽 기본 버튼이다.

## 이름 일괄 변경

파일 추가 → 작업 선택 → 값 입력 → 미리보기 → 이름 변경으로 읽혀야 한다.

1. 파일이 없으면 자소 분리 해결과 같은 형태의 빈 상태만 보인다. 파일 없이 규칙부터 만들 수 있는 보조 링크를 둔다.
2. 규칙이 없으면 “이름을 어떻게 바꿀까요?” 아래에 일상 작업 여섯 가지(텍스트 바꾸기, 앞에 붙이기, 뒤에 붙이기, 번호 붙이기, 공백 정리, 대소문자 바꾸기)를 예시와 함께 보여 준다.
3. 작업을 고르면 그 작업에 필요한 값만 보인다. 적용 부분·조건·고급 번호는 ‘세부 옵션’ 안에 둔다. 예시 이름으로 결과를 바로 확인하고, ‘작업 추가’로 여러 작업을 이어 붙일 수 있다.
4. 패턴(정규식)·파일 정보·CSV 목록·묶음 파일·프리셋·글자 저장 형식·번호 순서는 ‘고급 규칙’을 펼쳤을 때만 보인다.

규칙을 고친 뒤에는 ‘미리보기 갱신’이 강조되고 이름 바꾸기 버튼은 비활성이다. 갱신하면 이름 바꾸기가 primary가 된다. 사용자가 미리보기 갱신을 명시적으로 수행한 뒤에만 변경 가능한 상태가 되며, 갱신하지 않은 규칙은 stale로 표시하고 Rename 진입을 차단한다. 자소 분리 해결로 돌아가면 규칙은 실행 파이프라인에서 빠지지만 현재 세션의 초안은 보존할 수 있다.

넓은 창은 규칙과 결과를 나란히, 좁은 창은 한 흐름으로 세로 배치한다.

## 문자 구성 설명

분해형 이름 자체를 손상/오류로 표현하지 않는다. 원문 이름은 그대로 표시하고, 설명용 칸에서 첫 변경 grapheme의 내부 구성을 친숙한 glyph로 보여 준다. 상세 보기에서는 실제 Unicode scalar와 현재/NFC 구성을 확인할 수 있다.

표시용 자모·결합기호 glyph는 mutation 데이터로 다시 사용하지 않는다. 보이는 이름과 raw Unicode 판정의 책임을 분리한다.

## 사용자 용어

UI 문구는 일반 사용자의 목적 중심 표현을 쓴다. Unicode 정규화 용어는 화면에서 ‘글자 분리됨’, ‘자소 분리 합치기’, ‘글자 저장 형식’처럼 풀어 쓰고, 기술명이 필요한 곳만 ‘쉬운 이름 · 기술명’ 또는 괄호로 덧붙인다(예: 자소 분리 합치기 · NFC, 고급 패턴 바꾸기 (정규식)). 메타데이터는 ‘파일 정보’, CSV 매핑은 ‘CSV 목록으로 이름 바꾸기’, 파일 쌍은 ‘묶음 파일’로 부른다. 코드 값(U+, UTF-16)은 ‘글자 구성 자세히’ 안에서만 노출한다.

오류와 안내 문구는 무슨 일이 있었는지와 다음에 할 일을 함께 적는다. 새 문구는 Resources/Localizable.xcstrings에 ko/en/ja를 함께 추가하고, 일본어는 macOS 표기(フォルダ, ウインドウ)와 ‘ルール’, ‘再検査’로 통일한다.

## 테마와 표면

테마는 System, Dark, Light, Olive Archive 네 가지다. 새 설정이 없는 첫 실행의 제품 기본은 Olive Archive이고 저장된 사용자 선택은 보존한다. Olive sidebar의 기준 색은 #DDD8C5다.

macOS native toolbar, menu, sheet, popover, focus, overflow를 우선 사용한다. 장식용 과한 blur/animation과 반복 카드 중첩을 기본값으로 쓰지 않는다.

## 반응형 창

- 넓은 영역은 native sidebar + 결과 Table 중심. Table은 선택, 현재 이름(유형 아이콘 포함), 변경 후 이름, 상태 열을 쓴다.
- 좁은 영역은 같은 정보와 동작을 항목당 한 블록(현재 이름 ↳ 변경 후 이름, 상태)으로 재배치하며 기능을 삭제하지 않는다. 상세 보기와 경로 복사는 더블클릭·Return·context menu로 연다.
- 낮은 창은 세로 scroll을 제공하고 극단적으로 좁은 폭에서도 콘텐츠 접근 경로를 남긴다.
- 첫 실행 크기는 화면 visibleFrame을 기준으로 잡고 이후 일반 창 위치·크기·화면을 복원한다.
- 전체 화면/최소화 전환이 일반 window placement를 오염시키지 않는다.
- 크기 변경만으로 scan/selection/settings를 초기화하지 않는다.

수치 breakpoint는 실제 WindowLayout 구현이 원본이며 문서 수치를 고정 계약으로 복제하지 않는다.

## 접근성과 다국어

ko/en/ja를 지원한다. Pretendard/Pretendard JP와 시스템 fallback을 사용한다. 날짜·숫자는 앱에서 고른 언어의 형식으로 표시하고, macOS 폴더 접근 권한 안내와 Finder 서비스 이름도 세 언어로 제공한다. 아이콘만 있는 버튼에는 접근성 이름을 주고, 상태는 색만이 아니라 기호와 글자로 함께 표시한다. 긴 일본어·영어 문구, keyboard focus, Full Keyboard Access, VoiceOver, 큰 글자, 대비/투명도 설정을 고려한다.

자동 렌더와 model test는 Engineering Verification이다. 실제 VoiceOver/키보드/연속 resize/Finder gesture User QA를 대체하지 않는다. 남은 항목은 QA.md에 모은다.

## 변경 원칙

기존 화면은 기본적으로 KEEP이다. 실제 문제 근거가 있는 화면만 CHANGE, 필요한 상태만 ADD, 중복/혼란이 입증된 항목만 REMOVE한다. 새 참고자료나 만능프롬프트 적용만을 이유로 전체 UI를 재설계하지 않는다.
