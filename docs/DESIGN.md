# UI/UX 디자인 계약

## 제품 경험

첫 사용자는 복잡한 규칙 편집보다 자소 분리 문제 해결을 먼저 이해할 수 있어야 한다. 고급 사용자는 같은 앱에서 일괄 변경·프리셋·CSV·메타데이터·감시로 확장할 수 있어야 한다. 안전 상태와 실제 mutation 확인은 화면 단순화를 위해 숨기지 않는다.

주 방향은 Native · Quiet · Utility다. 제품 시그니처는 다음 네 가지다.

- 자소 분리 해결을 첫 화면에서 짧은 흐름으로 끝낸다. 처음 보는 사용자가 5초 안에 다음 행동을 알 수 있어야 한다.
- 실제 변경 전 현재 이름과 변경 후 이름, 제외/충돌 이유를 항상 확인할 수 있다.
- 일괄 변경은 일상 작업을 먼저 고르게 하고 고급 규칙은 펼쳤을 때만 보여 인지 부하를 낮춘다.
- 기록/Undo/Recovery는 성공 메시지보다 실제 파일 상태와 확인 가능성을 우선한다.

## 정보 구조

창의 왼쪽은 입력 상태를 따라 스스로 바뀐다. 사용자가 관리하는 toggle은 없다.

- 입력 없음: 펼친 navigation(아이콘 + 이름, 부제 없음)만 보이고 폴더 트리는 없다. 위쪽에 자소 분리 해결·파일 이름 일괄 변경·폴더 감시·복사한 글자 변환, 아래쪽에 작업 기록·설정·도움말. 주 메뉴와 아래쪽 메뉴 사이에 즐겨찾기 목록이 있다.
- 파일·폴더가 하나라도 추가됨: navigation이 아이콘만 있는 레일로 줄고(tooltip과 접근성 이름 제공), 바로 오른쪽에 추가한 파일·폴더의 트리가 나온다. 폴더를 누르면 목록이 그 안의 항목으로 좁혀지고 다시 누르면 풀린다. 무엇으로 좁혔는지는 트리의 선택 표시가 알려 주므로 목록 위에 따로 안내 줄을 두지 않는다. 창이 좁아 트리가 숨은 동안에만 ‘추가한 파일·폴더 N개’ 펼침과 ‘… 안의 항목만 표시 중 · 전체 보기’ 줄이 그 자리를 대신하며, 두 줄은 주변 글자와 같은 크기·굵기다.
- 모든 입력을 제거하면 즉시 펼친 navigation으로 돌아간다.
- 창이 좁으면(760pt 미만) content를 우선해 왼쪽 전체를 숨기고, 그동안에는 목록 위에 ‘추가한 파일·폴더 N개’ 펼침 줄이 대신 나온다.

레일의 아이콘은 펼친 navigation의 같은 항목과 같은 높이에 있어 상태가 바뀌어도 위치가 흔들리지 않는다. navigation 폭은 고정이고, 사용자가 구분선으로 조절하는 것은 트리 폭뿐이며 그 값만 따로 기억한다. 구분선으로 왼쪽을 접을 수는 없다.

트리에는 ‘전체 보기’, 추가한 항목, 하위 폴더를 둔다. 폴더 옆 숫자는 그 안의 변경 가능한 항목 수다. 좁힐 폴더가 없는 경우(파일 하나만 추가)에는 ‘전체 보기’를 두지 않는다. 추가한 항목은 context menu로 제거하고, 제목 옆 메뉴에 하위 폴더 검사 여부와 모두 제거가 있다. 폴더는 왼쪽 화살표로도, 이름을 더블클릭해서도 펼치고 접는다.

유료 등급이 없으므로 Pro badge나 ‘· Pro’ 표기는 쓰지 않는다.

## 창 chrome

title bar band와 왼쪽 navigation은 같은 색의 한 덩어리로 보이게 하고, 그 아래·오른쪽의 트리와 content는 canvas 색 panel 하나로 둔다. panel 위쪽 hairline은 title bar의 아래 경계이며, navigation(또는 레일)의 오른쪽 경계와 만나는 곳에서 둥근 모서리로 꺾여 아래로 이어진다. 트리와 content 사이는 hairline 하나로만 나눈다. card·그림자·굵은 테두리는 쓰지 않는다.

band에는 창 버튼에서 버튼 하나 폭 정도를 띄우고 앱 아이콘과 NameFix(약 15pt semibold)를 두고, content 위에는 현재 화면 이름을 창 제목으로 표시한다. 무언가 추가된 뒤에만 band 오른쪽에 결과 저장·다시 검사·추가 버튼이 나타난다. 앱 이름·화면 제목·버튼은 band의 같은 중심선에 놓는다.

앱 아이콘은 Icon Composer 문서(Resources/AppIcon.icon) 하나로 관리한다. 원본 그림을 canvas 전체를 채우는 한 장의 layer로 쓰고 유리 효과·하이라이트·그림자는 더하지 않으며, 바깥 모양은 시스템이 준다. 비트맵만 있는 아이콘은 macOS 26 이상에서 회색 판 안에 축소되어 보이므로 쓰지 않는다. macOS 14·15용 비트맵 아이콘은 빌드할 때 같은 문서에서 만들어진다. 원본 그림은 자체 여백(남색 배경)이 넓어 그대로 넣으면 Dock에서 다른 아이콘보다 작아 보이므로, 생성할 때 1.12배로 키워 여백을 잘라 낸다.

band는 버튼과 메뉴를 뺀 모든 지점에서 창을 움직여야 한다. 이를 위해 band 아래에는 SwiftUI hosting view를 두지 않는다. AppKit은 hosting view의 frame 전체를 ‘창 이동을 막는 영역’으로 계산하므로, hosting view가 band 밑까지 깔리면 창의 drag 영역이 비어 버리고 band의 일부 구간에서만 창이 움직인다. 그래서 band의 배경·앱 이름·drag strip은 AppKit view로 만들고, SwiftUI 화면은 band 바로 아래에서 시작한다. drag strip은 더블클릭을 시스템 설정대로 처리하고 band에 놓은 파일을 아래 화면으로 넘긴다. toolbar 버튼·창 버튼·구분선은 자기 동작이 우선한다.

메뉴 막대는 macOS 표준 구성(앱·파일·편집·보기·윈도우·도움말)을 따른다. 보기 메뉴의 ⌘1/⌘2가 두 파일 작업 화면을 전환하고, 윈도우 닫기·최소화·가리기·전체 화면은 시스템 표준 단축키를 쓴다. 결과를 CSV로 저장(⇧⌘E)과 최근 작업 되돌리기는 파일 메뉴, 글자 저장 형식 안내와 진단 보고서는 도움말 메뉴에 둔다. 메뉴·메뉴바 명령은 확인/결과 시트나 실행 중인 mutation 위에 다른 시트를 겹쳐 열지 않는다.

## 아이콘만 있는 control의 이름 표시

아이콘만 있는 control은 pointer를 올리면 자기 이름을 바로 옆에 보여 준다. 사용자가 아이콘의 뜻을 추측하게 두지 않는다. 시스템 tooltip은 사용자 확인에서 나타나지 않았고(원인 미확인) 뜨더라도 느리므로, 이런 control의 이름은 앱이 직접 그린다.

- 대상: 레일 아이콘, title bar band의 결과 저장·다시 검사·추가, 트리 제목 줄의 목록 옵션과 ⊗(모두 닫기), 추가한 항목 줄의 ×, 규칙 초기화·규칙 메뉴·설정 제거, 알림 닫기, 좁은 pane에서 아이콘만 남은 ‘필터·정렬’·‘선택’ 메뉴.
- 모양은 한 가지다: 본문 글자색 바탕에 canvas색 글자, 둥근 모서리의 작은 label. 지연 없이 나타나고, pointer가 벗어나거나 누르거나 입력·스크롤하면 사라진다.
- label은 클릭을 받지 않고 layout을 밀지 않는다. 레일은 화면 안에 겹쳐 그리고, 그 밖의 control은 클릭이 통과하는 작은 보조 창으로 그린다.
- keyboard·VoiceOver 사용자는 같은 이름을 accessibility label로, 덧붙일 설명은 hint로 얻는다.
- 글자가 이미 보이는 control에는 쓰지 않는다. 잘린 경로처럼 긴 글의 전체 보기는 시스템 tooltip(.help)에 맡긴다.
- band의 세 버튼은 이 label을 달 수 있도록 앱이 만든 button을 NSToolbar item의 view로 넣는다. 동작·활성 조건·배치는 toolbar item 그대로다.

## 간격 기준

나란히 놓인 영역은 같은 선에서 시작한다. 값은 코드의 Metrics가 원본이며 여기에는 역할만 적는다.

- page inset: panel 가장자리와 내용 사이. 트리, 규칙 pane, 목록 pane에 똑같이 적용한다.
- pane header 높이: 트리 제목, ‘변경 규칙’, 목록 위 control 줄의 고정 높이. 상태가 바뀌어도 높이는 변하지 않는다.
- gap: pane 안의 줄 사이.
- control gap: 한 줄 안의 control 사이.

## 상태 줄

개수, 지금 하는 일, 알림은 pane 맨 아래 줄의 왼쪽, primary 버튼과 같은 줄에 나온다(D-018). 별도의 상태 표시줄은 두지 않는다. 진행 상황과 알림이 목록 위에 끼어들지 않으므로 표 위치는 변하지 않는다.

- 순서: “전체 N개 중 M개 표시”(숨은 선택이 있으면 그 수를 경고색으로) → 진행 상황(진행 표시, 하는 일, 경과 시간, 취소) → 알림. 알림은 “규칙 입력값 확인 필요”처럼 짧은 요약만 보이고, 누르면 전체 문구를 선택 가능한 popover로 표시하며 × 로 닫는다. 요약이 따로 없는 알림은 첫 문장만 보인다.
- 한 줄에 다 들어가지 않으면 세로로 쌓이고, 그래도 좁으면 primary 버튼이 아랫줄로 내려간다.
- 입력이 없는 첫 화면에는 이 줄이 없다. 그 상태에서 알림이나 진행 상황이 생기면 화면 왼쪽 아래에 같은 모양으로 잠깐 나온다.

## 지원 범위 밖의 위치

지원하는 디스크(APFS)에서는 아무 안내도 보이지 않는다. 전문적인 디스크 정보 화면은 만들지 않는다. 항목이 놓인 위치 때문에 이름을 바꾸지 않는 경우에만 짧게 알린다.

- 상태 칸: 항목이 고장 난 것처럼 보이지 않도록 ‘지원하지 않는 항목’ 대신 위치를 말한다. ‘— 읽기 전용’, ‘— 이 드라이브는 제외’(exFAT·FAT, HFS+, 네트워크, 그 밖의 형식), ‘— 동기화 폴더는 제외’. 자세한 이유는 줄의 도움말과 자세히 보기에 나온다.
- 상태 줄 알림: 검사 결과에 그런 항목이 있으면 이유를 한 줄로 한 번 보여 준다(정보 아이콘, 예: “exFAT·FAT 드라이브: 이름 변경 제외”). 누르면 전체 설명이 나온다. 그 위치를 닫으면 알림도 사라진다.
- 이유 문구는 세 가지를 담는다: 무엇을 하지 않는지, 파일에 문제가 있는 것이 아니라는 것, 할 수 있는 일(Mac의 디스크로 복사하면 정리할 수 있음).
- 읽기 전용 APFS는 바뀔 이름을 계속 보여 준다(확인만 가능). cloud 동기화 폴더는 내용을 읽지 않고 폴더 한 줄만 보여 준다.
- 디스크를 통째로 추가하면 디스크 줄에는 ‘디스크 자체의 이름은 바꾸지 않는다’고 나오고 안의 항목은 평소처럼 검사한다.
- 다시 연결한 디스크의 기록은 같은 디스크로 확인되면 그대로 되돌릴 수 있다. 확인할 수 없는 예전 기록은 이유를 알리고 그대로 둔다.

## 폴더 접근 요청

앱은 사용자가 고른 폴더 안에서만 작업할 수 있다. 사용자는 이것을 기능의 제한으로 느끼지 않아야 하고, sandbox·bookmark·entitlement 같은 말을 보지 않는다(D-033, D-034).

- 따로 권한을 안내하는 첫 화면은 없다. 필요한 순간에 필요한 폴더 하나만 요청한다.
- 폴더를 추가하면 바로 동작한다. 파일만 추가했을 때는 그 파일이 든 폴더를 고르는 창이 그 폴더를 연 채로 뜬다. 창에는 무엇을 위해 필요한지와 파일 내용은 바꾸지 않는다는 것을 적는다.
- 취소하면 아무것도 바뀌지 않는다. 그 항목의 상태는 ‘— 폴더 선택 필요’(오류가 아님), 상태 줄에는 ‘폴더 선택 필요’ 안내가 나오고 누르면 ‘폴더 선택…’ 버튼이 있다.
- 앱을 다시 연 뒤 되돌리기는 그대로 된다. 접근을 다시 얻지 못한 경우에만 “이 작업을 되돌리려면 ‘폴더’ 폴더를 다시 선택해 주세요”라고 요청하고, 고르면 되돌리기 확인으로 이어진다.
- 추가한 폴더 자체의 줄은 이름이 바뀌지 않으면 여느 줄과 같다. 이름이 바뀔 때만 상태가 ‘— 상위 폴더 선택 필요’이고, 상태 줄에 ‘폴더 이름도 바꾸려면 상위 폴더 선택’과 ‘상위 폴더 선택…’ 버튼이 나온다. 창은 저절로 뜨지 않는다. 버튼을 누르면 상위 폴더를 연 채로 창이 뜨고, 고르면 다시 검사해 그 폴더도 대상이 된다(D-037).
- 폴더를 요청하는 안내에는 할 일이 한 번의 클릭 거리에 있어야 한다. ‘폴더 선택 필요’와 ‘상위 폴더 선택’ 안내 옆에 버튼을 바로 둔다. 여러 폴더가 필요하면 창의 안내에 남은 폴더 수를 적는다. 다른 폴더를 고르면 받지 않고 ‘다른 폴더를 선택했습니다’로 알린다.
- 즐겨찾기·최근 폴더·폴더 감시에는 따로 권한을 묻는 화면이 없다. 폴더가 옮겨지거나 지워졌을 때는 기존의 ‘다시 선택’을 쓴다.
- 앱 메뉴에 업데이트 명령은 없다. App Store가 업데이트한다(D-038).

## Windows에서 쓸 수 없는 이름

‘필터·정렬’의 맨 아래 항목으로만 고를 수 있고 기본 화면에는 드러나지 않는다. 자세히 보기는 바뀔 이름에 문제가 있을 때만 무엇이 문제인지 알려 준다. 알려 주기만 하며 이름을 바꾸지 않는다(D-030).

## 추가한 항목 닫기

추가한 파일·폴더를 닫고 첫 화면으로 돌아가는 길은 항상 보인다. 트리 제목 줄의 ⊗(모두 닫기), 추가한 항목 줄에 pointer를 올리면 나오는 ×(이 항목 닫기)와 context menu, 파일 메뉴의 모두 닫기(⇧⌘W)가 같은 동작이다. 왼쪽 영역이 숨겨진 좁은 창에서는 ‘추가한 파일·폴더’ 펼침 안에 있다. 닫기는 목록에서 빼는 것이며 파일은 바뀌지 않는다.

## 처음 소개 (온보딩)

앱을 열면 4쪽짜리 소개가 sheet로 나온다(D-019). 자소 분리 해결, 바꾸기 전 확인과 되돌리기, 규칙으로 일괄 변경, 전 기능 무료·이 Mac 안에서만 처리 — 장점만 짧게 보여 준다. 쪽마다 색이 다른 그림과 색 아이콘을 쓰고, 앱 테마와 상관없이 항상 밝은 색으로 그린다(버튼·체크 표시도 자체 색). ‘다시 보지 않기’를 켜고 닫으면 다음 실행부터 나오지 않으며, 설정 맨 아래 카드의 ‘소개 다시 보기’와 도움말 메뉴에서 언제든 다시 볼 수 있다. 설정이나 사용 방법에서 열었다면 닫을 때 그 화면으로 돌아가고, 실행 직후나 메뉴에서 열었다면 그냥 닫힌다. 소개는 설정 위에 겹쳐 뜨는 창이 아니라 같은 sheet의 내용이 바뀌는 것이다. sheet는 닫히는 동안에도 닫히기 직전의 내용을 그대로 보여 준다.

## 사용 방법과 설정

사용 방법 sheet는 앱 아이콘과 한 줄 설명, 번호가 붙은 3단계 카드, 주제별 카드(자소 분리란, 안심하고 이름만 수정, 파일 이름 일괄 변경), 단축키 표 순서다. 주제마다 색 아이콘 tile을 쓴다.

설정의 첫 묶음(테마·행 간격·열 너비)에는 제목과 아이콘을 두지 않는다. 모든 켬/끔 항목은 이름이 왼쪽, switch가 오른쪽 끝이다. 맨 아래에는 앱과 개발자를 소개하는 카드 하나가 있다. 위쪽은 앱: 아이콘, ‘MOONGCHI’ 작은 표제, 앱 이름, 한 줄 설명, 그리고 ‘무료’ 표시·버전·지원 기기, 세 문장 요약(하는 일, 전 기능 무료, 이 Mac 안에서만 처리), 사용 방법·소개 다시 보기 버튼. 아래쪽은 ‘개발자 소개’: AILO 로고(vector 외곽선을 화면에 직접 그림), AILO WORKS와 한 줄 소개, 뭉치 웹사이트(moongchi.ailoworks.com) 버튼과 설명, 폰트 라이선스. 다른 뭉치 앱의 정보 화면과 같은 구성·문구를 쓴다. 링크는 사용자가 눌렀을 때 기본 브라우저로 열리며 앱 자체는 네트워크 통신을 하지 않는다. ‘버그 신고 및 문의’ 버튼은 사용자의 메일 앱에서 ailo@ailoworks.com으로 새 메일을 열고, 주소는 복사할 수 있게 옆에 글자로도 보인다. sheet가 좁으면 줄들이 세로로 쌓인다.

## 즐겨찾기와 폴더 감시

즐겨찾기는 자주 쓰는 폴더로 가는 shortcut이다(D-021). 즐겨찾기에 추가하는 것만으로 FSEvents나 background 감시를 시작하지 않으며, 즐겨찾기를 고르면 그 폴더를 현재 입력에 추가하고 그 시점의 상태를 검사한다. 실시간 감시는 사용자가 ‘폴더 감시’에 명시적으로 등록한 폴더만 수행한다.

- 첫 화면: 펼친 navigation의 주 메뉴 아래에 ‘즐겨찾기’ 목록이 있다. 제목 줄의 +로 폴더를 추가하고, 항목을 누르면 열린다. pointer를 올리면 나오는 ×와 context menu로 제거하며 context menu에는 폴더 다시 선택·Finder에서 보기도 있다. 비어 있으면 한 줄 안내만 보인다.
- 열 수 없는 즐겨찾기(옮겨짐·삭제됨·접근 권한 없음)는 경고 아이콘과 ‘찾을 수 없음 · 다시 선택’으로 표시하고, 누르면 폴더를 다시 고르게 한다. 고른 순간에야 문제가 드러난 경우에도 아래 알림으로 알리고 같은 표시로 바꾼다.
- 폴더를 넣은 뒤(아이콘 레일 상태): band의 추가(+) 메뉴에 즐겨찾기 목록과 ‘즐겨찾기 폴더 추가…’가 있고, 트리의 추가한 폴더 context menu에 ‘즐겨찾기에 추가/제거’가 있다. 파일 메뉴에도 ‘즐겨찾기 폴더 추가…’가 있다.
- 왼쪽 영역이 숨은 좁은 창의 첫 화면에서는 즐겨찾기를 메뉴로 제공한다.
- 최근 폴더와의 구분: 최근 폴더는 사용자가 기억을 켠 경우에만 남는 지나간 기록이고, 즐겨찾기는 사용자가 직접 고정한 것이다. 같은 폴더가 둘 다에 있으면 즐겨찾기에만 나열한다. 최근 폴더가 사라졌으면 알리고 목록에서 뺀다.
- 즐겨찾기 제거는 shortcut만 지우며 폴더와 파일은 건드리지 않는다.

## 상태별 노출 (Progressive Disclosure)

화면은 현재 상태에 필요한 control만 보여 준다. 기능을 지우지 않고 처음 보이는 시점만 늦춘다.

- 입력 없음: 가운데 빈 상태가 유일한 입력 화면이다. 제목, “여기에 놓으세요”, 파일 내용을 바꾸지 않는다는 안내, 파일 선택·폴더 선택, 하위 폴더 검사 여부만 둔다. 통계·검색·필터·정렬·선택·실행 버튼은 없다. 최근 폴더는 사용자가 기억하도록 켠 경우에만 보인다.
- 검사 중: 맨 아래 줄 왼쪽에 진행 상황과 취소. 아직 보여 줄 항목이 없으면 목록 자리에 하는 일을 표시한다.
- 결과: 목록 위 한 줄(요약 chip인 정리할 이름·충돌·선택과 충돌 번호 제안 → 검색 → ‘필터·정렬’ 메뉴 → ‘선택’ 메뉴), 결과 목록, 그리고 pane 맨 아래 primary 버튼 하나. 한 줄에 들어가지 않으면 두 메뉴가 아이콘만 남고, 그래도 좁으면 chip과 검색이 두 줄로 나뉜다. 결과 목록은 열이 폭을 나눠 쓰며 가로 스크롤 막대를 보이지 않는다.
- 완료: 결과 시트에서 작업 기록과 되돌리기.

요약 항목은 그 자체가 해당 항목만 보는 필터다. 충돌은 있을 때만 보인다. 큰 gradient 통계 카드, full-width 입력 버튼, 카드 안의 카드는 쓰지 않는다. 표가 화면의 중심이다. drag & drop은 모든 상태에서 창 전체가 받는다.

## 자소 분리 해결

입력 → 검사/변경 결과 확인 → 선택한 이름 합치기 → 최종 확인 순서다. 분리 저장된 글자를 항상 하나로 합치며(NFC) 사용자가 형식을 고를 필요가 없다. 분리 형식이 필요한 드문 경우는 일괄 변경의 규칙 추가 → 글자 저장 형식에서 바꾼다. 일괄 변경의 초안을 몰래 실행하지 않는다.

최종 확인 시트는 바뀌는 개수, 제외 개수, 숨은 선택, 되돌리기 가능 여부, 항목별 현재 이름 → 변경 후 이름을 보여 준다. 버튼은 macOS 관례대로 취소가 왼쪽, 실행이 오른쪽 기본 버튼이다.

## 파일 이름 일괄 변경

파일 추가 → 규칙 추가 → 값 입력 → 미리보기 → 이름 변경으로 읽혀야 한다. 파일이 없으면 자소 분리 해결과 같은 형태의 빈 상태만 보이고, 파일 없이 규칙부터 만들 수 있는 보조 링크를 둔다.

넓은 창은 정확히 두 pane이다. 왼쪽 ‘변경 규칙’, 오른쪽 결과 목록. 왼쪽 header와 오른쪽 control 줄은 같은 선에서 시작하고 높이가 같다. 오른쪽에는 ‘미리보기’ 같은 제목을 두지 않는다. 화면에 별도의 큰 질문 제목이나 작업 카드 목록, 상시 펼쳐진 ‘고급 규칙’ 영역도 두지 않는다.

기본 대상은 보이는 일반 파일이다(D-022). 추가한 폴더 자체·하위 폴더·숨김 항목은 목록에 그대로 보이되 상태가 ‘대상 아님’이고 선택할 수 없으며 번호도 차지하지 않는다. 이 화면에 들어오면 목록을 이 기준으로 다시 검사한다. 대상을 넓히는 길은 ‘+ 규칙 추가’ → 고급 → ‘대상 범위’ sheet의 두 스위치(‘폴더 이름도 변경’, ‘숨김 파일 포함’)뿐이고, 켜면 규칙 목록에 요약 줄로 남는다.

- 규칙 추가: 왼쪽 header의 ‘+ 규칙 추가’ 하나로 시작한다. popover에서 기본(텍스트 바꾸기, 앞·뒤에 붙이기, 번호 붙이기, 공백 정리, 대소문자 바꾸기), 고급(고급 패턴, 파일 정보, 글자 저장 형식, 대상 범위, 순서 지정, CSV 목록, 묶음 파일, 프리셋), 그 밖의 규칙을 고른다. 줄 전체가 클릭 영역이다.
- 규칙 목록: 규칙마다 켜기 checkbox, 이름, 한 줄 요약(예: ‘초안’ → ‘최종’, 1부터 · 3자리)만 보인다. 규칙을 누르면 그 규칙의 값만 펼쳐지고, 적용 부분·조건·고급 번호는 ‘세부 옵션’ 안에 둔다. 순서 바꾸기와 제거는 줄 끝 메뉴와 context menu에 있다. 규칙이 하나도 없이 화면을 열면 ‘텍스트 바꾸기’ 규칙 하나가 펼쳐진 채로 들어 있다. 찾을 글자가 아직 비어 있는 규칙은 아무 일도 하지 않으므로 목록 계산·저장에서 빠지고 오류로 다루지 않는다.
- 규칙이 아닌 고급 설정(글자 저장 형식, 대상 범위, 순서 지정, CSV 목록, 묶음 파일, 프리셋)은 각각 전용 sheet에서 다루고, 기본값과 달라진 설정은 규칙 목록에 요약 줄로 나타나 숨지 않는다.
- 적용 예시: 목록 아래에, 추가한 이름 가운데 지금 규칙으로 실제로 바뀌는 이름 하나를 변경 전 → 후로 보여 준다. 바뀌지 않는 이름을 예시로 내놓지 않는다. 규칙에 걸리는 이름이 없으면 그렇다고 한 줄로 알리고, 채워진 규칙이 없으면 아무것도 보이지 않는다.

목록이 규칙과 어긋나면 control 줄 맨 앞에 ‘업데이트 필요’ chip이 나타난다. 요약 chip과 같은 크기이고 경고색이며, 누르면 바뀐 규칙으로 목록을 다시 계산한다(별도의 ‘미리보기 갱신’ 버튼은 없다. toolbar의 다시 검사와 헷갈린다는 사용자 지적). 줄 높이는 변하지 않고 표를 밀어내는 banner는 쓰지 않는다. 이 상태에서는 이름 바꾸기 버튼이 비활성이며 tooltip과 접근성 hint로 이유를 알린다. 사용자가 명시적으로 다시 계산한 뒤에만 변경 가능한 상태가 된다. 자소 분리 해결로 돌아가면 규칙은 실행 파이프라인에서 빠지지만 초안은 보존되고, 적용했던 규칙 조합은 재시작 뒤에도 초안으로 남는다. 앱은 항상 자소 분리 해결 화면에서 시작한다(D-020).

좁은 창은 규칙과 미리보기를 한 흐름으로 세로 배치한다.

## 문자 구성 설명

분해형 이름 자체를 손상/오류로 표현하지 않는다. 원문 이름은 그대로 표시하고, 설명용 칸에서 첫 변경 grapheme의 내부 구성을 친숙한 glyph로 보여 준다. 상세 보기에서는 실제 Unicode scalar와 현재/NFC 구성을 확인할 수 있다.

표시용 자모·결합기호 glyph는 mutation 데이터로 다시 사용하지 않는다. 보이는 이름과 raw Unicode 판정의 책임을 분리한다.

## 사용자 용어

UI 문구는 일반 사용자의 목적 중심 표현을 쓴다. Unicode 정규화 용어는 화면에서 ‘글자 분리됨’, ‘분리된 글자 합치기’, ‘글자 저장 형식’처럼 풀어 쓰고, 기술명이 필요한 곳만 ‘쉬운 이름 · 기술명’ 또는 괄호로 덧붙인다(예: 분리된 글자 합치기 · NFC, 고급 패턴 바꾸기 (정규식)). 메타데이터는 ‘파일 정보’, CSV 매핑은 ‘CSV 목록으로 이름 바꾸기’, 파일 쌍은 ‘묶음 파일’로 부른다. 코드 값(U+, UTF-16)은 ‘글자 구성 자세히’ 안에서만 노출한다.

오류와 안내 문구는 무슨 일이 있었는지와 다음에 할 일을 함께 적는다. 새 문구는 Resources/Localizable.xcstrings에 ko/en/ja를 함께 추가하고, 세 언어는 기능과 조작이 같되 문장을 단어 대 단어로 맞추지 않는다. 각 언어 사용자가 그 문제를 만나는 방식으로 쓴다.

- 한국어: 자소 분리, 파일 이름, 일괄 변경, 작업 기록, 되돌리기(끝난 작업)·복구(중단된 작업), 검사(앱이 이름을 살핌)·확인(사용자가 봄), 미리보기 업데이트, 폴더 감시, 이 Mac. ‘분리된 글자 합치기 · NFC’처럼 합치는 대상은 글자다.
- 영어: 첫 화면은 Fix Broken Names, 문제는 “names that look broken on other devices”(악센트가 글자 옆에 따로 보임, 글자가 나뉨, 검색이 안 맞음)로 설명한다. 한글은 예시의 하나다. 동사는 fix, 상태는 split, 제외는 skipped, 검사는 scan, 표기는 filename. 메뉴·버튼·sheet 제목은 title-style, 그 밖은 sentence-style. 하나일 때의 문구는 key + One으로 둔다(Fix 1 Name).
- 일본어: 첫 화면은 文字を整える, 문제는 濁点・半濁点が離れて見える로 설명한다. 사용자의 동작은 整える, 일어나는 일은 1文字にまとめる. 合成・結合・修復는 쓰지 않는다. スキャン, 絞り込み, 詳細, 履歴, 処理(진행 중)·操作(기록된 한 번), 全角と半角の違い는 다른 문제라고 밝힌다. macOS 표기(フォルダ, ウインドウ, Appleシリコン, 書類, ペースト)를 따른다.
- 기본 화면에 Unicode·NFC·NFD·정규식·metadata 같은 기술명을 내세우지 않는다. 이름 변경 확인 창은 글자 저장 형식이 기본(합치기)이 아닐 때만 그 형식을 적는다.

## 테마와 표면

테마는 System, Dark, Light, Olive Archive 네 가지다. 새 설정이 없는 첫 실행의 제품 기본은 Olive Archive이고 저장된 사용자 선택은 보존한다. Olive sidebar의 기준 색은 #DDD8C5다.

macOS native toolbar, menu, sheet, popover, focus, overflow를 우선 사용한다. 장식용 과한 blur/animation과 반복 카드 중첩을 기본값으로 쓰지 않는다.

## 반응형 창

- 넓은 영역은 native sidebar + 결과 Table 중심. Table은 선택, 현재 이름(유형 아이콘 포함), 변경 후 이름, 상태 열을 쓴다.
- 좁은 영역은 같은 정보와 동작을 항목당 한 블록(현재 이름 ↳ 변경 후 이름, 상태)으로 재배치하며 기능을 삭제하지 않는다. 상세 보기와 경로 복사는 더블클릭·Return·context menu로 연다.
- 낮은 창은 세로 scroll을 제공하고 극단적으로 좁은 폭에서도 콘텐츠 접근 경로를 남긴다.
- 첫 실행 크기는 화면 visibleFrame을 기준으로 잡고 이후 일반 창 위치·크기·화면을 복원한다.
- 전체 화면/최소화 전환이 일반 window placement를 오염시키지 않는다.
- 크기 변경만으로 scan/selection/settings를 초기화하지 않는다.

수치 breakpoint는 실제 WindowLayout 구현이 원본이며 문서 수치를 고정 계약으로 복제하지 않는다.

## 접근성과 다국어

ko/en/ja를 지원한다. Pretendard/Pretendard JP와 시스템 fallback을 사용한다. 날짜·숫자는 앱에서 고른 언어의 형식으로 표시하고, macOS 폴더 접근 권한 안내와 Finder 서비스 이름도 세 언어로 제공한다. 아이콘만 있는 버튼에는 접근성 이름을 주고, 상태는 색만이 아니라 기호와 글자로 함께 표시한다. 긴 일본어·영어 문구, keyboard focus, Full Keyboard Access, VoiceOver, 큰 글자, 대비/투명도 설정을 고려한다.

자동 렌더와 model test는 Engineering Verification이다. 실제 VoiceOver/키보드/연속 resize/Finder gesture User QA를 대체하지 않는다. 남은 항목은 QA.md에 모은다.

## 변경 원칙

기존 화면은 기본적으로 KEEP이다. 실제 문제 근거가 있는 화면만 CHANGE, 필요한 상태만 ADD, 중복/혼란이 입증된 항목만 REMOVE한다. 새 참고자료나 만능프롬프트 적용만을 이유로 전체 UI를 재설계하지 않는다.

## 이름을 더 빠르게 바꾸기 (D-036)

설정 ‘일반’에 switch 하나와 설명 한 문단을 둔다. 설명은 무엇이 그대로이고(내용 변경 없음, 덮어쓰지 않음) 무엇을 감수하는지(전원이 갑자기 꺼지면 마지막 몇 항목을 직접 확인), 외장 드라이브는 항상 안전한 방식이라는 것을 말한다. 기술 용어(fsync, journal)는 쓰지 않는다. 기본 방식으로 200개 이상을 5초 넘게 바꾼 뒤에는 아래 한 줄 안내로 이 설정을 한 번만 알린다.

## 일괄 변경의 규칙은 실행마다 새로 시작

앱을 다시 열면 변경 규칙은 비어 있다(빈 ‘텍스트 바꾸기’ 하나로 시작). 지난번 규칙이 남아 있다가 그대로 실행되는 일을 막기 위해서다. 다시 쓸 규칙은 프리셋으로 저장해 불러온다. 바뀌는 이름이 없고 폴더가 있으면 규칙 아래에 폴더 안내와 ‘폴더 이름도 변경’ 버튼을 보이고, 버튼은 목록을 바로 갱신한다. 목록 위 요약 항목은 누르면 그 항목만 보이는 필터이며 개수가 0이면 눌리지 않는다.
