# Moongchi NameFix 무료와 Pro 확장 개발 계획

> v1.0 후속: 사용자 상용 출시 요청으로 Release·서명·패키지 작업을 진행한다. SOURCE_RACE는 보완 후 알려진 제한과 실제 출시 외부 조건으로 구분하며 최신 판단은 [V1_RELEASE_STATUS.md](V1_RELEASE_STATUS.md)가 우선한다. 이전 확장 단계 정책은 이력으로 보존한다.

작성일: 2026-10-04 · 대상: 개발자와 개발 AI · 상태: 계획 작성 완료, 확장 구현은 미착수

목표는 Apple Silicon용 글로벌 파일 이름 정리 앱이다. 국내 제품은 직접 경쟁 기준으로, 해외 제품은 기능과 사용 흐름의 비교 기준으로 삼는다. 해외 매출이 더 클 것이라는 판단은 사업 가설이며 판매 실적으로 검증된 사실이 아니다. 무료는 Unicode 정리·기본 일괄 이름 변경·Mac 접근성과 안전한 사용 경험을 완성하고, Pro는 고급 규칙과 반복 업무의 저장·연계를 제공한다. 2026-10-04 후속 사용자 지시에 따라 무료 사용자가 옮겨올 이유를 강화했으며 아래 정책을 이전 무료/Pro 구분보다 우선 적용한다.

이 문서는 단계별 구현 범위와 완료 기준이다. [작업 목록](EXPANSION_TASKS.md)의 첫 미완료 작업부터 [일괄 개발 실행 지침](EXPANSION_EXECUTION.md)에 따라 진행한다. 이 문서 작성은 기능 구현 완료를 뜻하지 않는다.

## 적용 순서와 기존 요구사항 변경

최신 사용자 지시, 적용되는 AGENTS.md, 이 확장 계획, 기존 Master의 비충돌 요구사항 순으로 해석한다. 사용자 지시는 저장소 규칙보다 우선한다. 현재 프로젝트와 상위 경로에서 AGENTS.md는 발견되지 않았다. 추후 파일이 생기면 먼저 읽는다. 인수인계 원문과 과거 검증 근거는 보존한다.

| 기존 기준 | 이번 확장에 적용할 기준 |
|---|---|
| NFC 변경만, NFD는 표시 전용 | 무료에서 명시적 NFC 및 NFD 출력 선택 제공 |
| 범용 변경·정규식 제외 | 기본 변경과 기본 규칙 조합은 무료, 정규식·조건·업무 연계는 Pro |
| 파일 내용을 제품에서 읽지 않음 | 기본 검사는 계속 이름만 처리. 사용자가 메타데이터 규칙을 선택한 경우에만 지원 형식의 메타데이터를 읽기 전용으로 추출 |
| 계정·서버 없음 | 파일 처리와 무료 사용에 계정 불필요. Pro 권한 공급자는 별도 경계로 격리하며 구매 방식은 미결정 |
| Dark 최초 기본값 | 기존 사용자 지시대로 Olive Archive 기본값, 저장한 테마 보존 |
| Intel 포함 전체 빌드·패키지 | macOS 14 이상 arm64 전용. 개발 중 Debug·관련 테스트, Release는 사용자 요청 때만 |
| 원본 Phase 완료 기록 | 기존 Unicode 앱의 과거 기록. 이번 확장 완료 증거로 사용하지 않음 |

파일 내용 수정·삭제·덮어쓰기·copy-delete 대체 이동은 금지한다. 기본 화면의 카드·정보·선택·Inspector·기록·테마·반응형 창·마지막 크기 복원을 보존한다. 일반 구현 선택과 단계 전환에 중간 승인을 요청하지 않는다.

## 무료 사용자 유입 정책

정책 판단은 **자소분리 전용 앱보다 기능 폭을 체감상 꽤 넓게 제공**하는 것이다. 같은 변환에 테마와 버튼만 더하면 이미 쓰는 앱을 바꿀 이유가 약하다. 무료에서 한글 문제 해결 이후의 일상적인 이름 정리까지 끝내게 하고, Pro는 반복 작업의 저장·고급 조건·외부 자료 활용에 가치를 둔다. 이는 전환을 높이기 위한 가설이며 사용자 이동이나 판매 증가가 입증된 결과는 아니다.

반디네이머의 공식 주요 기능은 형식 확인과 양방향 변환이다. FileNic은 메뉴바 접근, 자모야는 텍스트, hangul-nfc는 Finder/CLI/감시가 강점이다. 개별 기능을 모으는 것에 더해 기본 일괄 이름 변경을 무료로 제공한다. 다만 hangul-nfc의 무료 감시처럼 경쟁 제품에서 무료인 기능이 우리 Pro에 포함될 수 있으며 모든 국내 앱의 모든 기능보다 우위라고 주장하지 않는다. 국내 앱의 인기 순위·사용자 수는 확인하지 않았으므로 ‘가장 인기 있는 앱보다 우수’라는 표현을 쓰지 않는다.

| 사용자에게 제공할 가치 | 무료 정책 | Pro 구매 이유 |
|---|---|---|
| 자소분리 문제를 이해하고 해결 | NFC/NFD, 시각화, 텍스트 도구, Finder/메뉴바 | 기본 문제 해결은 결제 불필요 |
| 일상 파일 이름을 한 번에 정리 | literal 치환, 앞뒤/위치 문자 편집, 공백·대소문자, 명시적 확장자 편집, 일반 순번 | 정규식·조건별 처리·고급 순번 |
| 여러 기본 변경을 한 번에 완료 | 무료 규칙끼리 순서 조합·재정렬·preview, 단계 수 인위적 제한 없음 | 사용자 프리셋의 저장·복제·공유·가져오기, 조건부 규칙 |
| 처음부터 편리하게 사용 | 무료 규칙만 사용하는 기본 제공 예제, 마지막 무료 작업 설정 자동 복원 | 여러 업무용 레시피를 이름 붙여 관리 |
| 작업을 믿고 실행·복구 | 개수/속도 차등 없음, 안전·Undo·Recovery·기본 결과 목록 내보내기 | 안전 기능은 결제 불필요 |

무료 기본 조합 예: `NFC 정리 → 공백 정리 → 프로젝트명 접두사 → 001부터 번호`를 한 번의 미리보기와 확인으로 수행한다. 사용자가 단일 규칙씩 여러 번 파일을 바꿔야 하도록 제한하지 않는다. Pro 예: `CSV 매핑 → 사진 촬영일 → 파일 쌍의 같은 번호 → 업무 프리셋 저장`이다.

무료는 기간·횟수 제한 없는 완결된 제품으로 제공한다. 광고·회원가입·강제 구매창·성능 저하를 유입 수단과 맞바꾸지 않는다. Pro 안내는 고급 기능을 사용하려는 지점에서 기능과 가격 연결 상태를 명확히 보여 주며 파일을 선택하거나 실행한 뒤 갑자기 결제를 요구하지 않는다. 안내를 닫아도 무료 작업·설정·선택을 보존한다. 무료로 제공한 기능은 이후 조용히 유료로 회수하지 않는다.

무료 설정 자동 복원은 마지막 규칙과 파라미터만 의미하며 파일 선택·경로·clipboard를 자동 저장하지 않는다. 최근 폴더의 기존 opt-in 정책을 유지한다. Pro 자료는 권한 상실 시 읽기·백업용 내보내기를 허용한다.

효과는 구현 후 선택 참여 사용성 평가로 확인한다. 기존 무료 도구 이용자에게 같은 fixture로 자소분리 해결, 기본 이름 정리, 작업 복원을 수행하게 하고 완료 여부·소요 시간·도움 요청·전환 의향과 이유를 기록한다. 국내와 해외 참여 결과를 구분하고 초기에 각 그룹 5명 이상을 탐색적으로 모집한다. 이 표본으로 시장 전환율을 추정하지 않는다. 무료 과제에서 Pro가 요구되면 정책 구현 실패이며, 기존 도구 대비 이점이 없다는 응답은 UI와 범위 재검토 근거다. Pro 가치는 반복 과제의 재설정 시간 절감과 구매 의향으로 별도 평가한다. 파일명·경로 자동 수집과 분석 SDK는 추가하지 않는다. 참여자가 없으면 NOT_AVAILABLE로 두고 개발 결함이나 유입 성공으로 바꾸지 않는다.

| P06 | CSV/TSV와 결과 목록 | 기본 결과 목록 내보내기·기록·진단 | 이름 매핑 가져오기·열 매핑·업무 처리 | 없음 |
| P07 | 파일 속성·사진·음악·영상·문서 메타데이터 이름 구성 | 기본 검사만 | 규칙별 읽기·실행 | 없음 |
| P08 | RAW/JPEG/sidecar 등 같은 기본 이름 파일 쌍 | 기본 검사만 | 묶음 이름 제안 | 없음 |
| P09 | 폴더 감시·대기열·저장 규칙 및 CLI 연계 | 수동 검사 | 감시·규칙 연계 | 없음 |

F/P 접두사는 기존 기능 추적 ID이며 요금제 판정에 사용하지 않는다. 일부 P ID에도 무료 기능이 포함된다. 요금제 판정은 실제 규칙 종류와 파라미터 capability에 따른다. 기본 필터/검색/선택과 규칙별 조건 분기는 구분한다. Free의 전역 선택·필터는 계속 무료다.

무료에서도 Pro로 수행했던 작업의 기록 조회·Undo·Recovery를 사용할 수 있다. 권한이 없어져도 프리셋·journal을 삭제하지 않는다. 네트워크 실패와 환불/취소를 구분하고, 실행 중인 transaction의 권한은 시작 시 고정하여 작업 도중 취소하지 않는다. 무료 경로는 권한 서버 장애에 의존하지 않는다.

## 공통 안전과 사용 계약

1. 화면 이름, 원시 filename bytes, 볼륨 lookup identity를 분리한다. NFC와 NFD 차이는 Swift String 동등성으로 판별하지 않는다. raw bytes는 journal에 base64로 보존한다.
2. 기본 출력은 NFC이며 NFD는 사용자가 목적을 알고 선택한다. NFD라는 이유만으로 손상이라고 부르지 않는다. 상태는 선택한 변환 목표를 기준으로 계산한다. NFKC/NFKD는 분석 전용으로 유지한다.
3. 모든 입력 경로는 동일한 Preview → 충돌 검사 → 명시 확인 → fresh 검증 → 직렬 transaction → 결과 검증·journal 경로를 사용한다. 메뉴바·CLI·감시 기능에 우회 executor를 만들지 않는다.
4. 파일 내용·태그·EXIF·ID3는 수정하지 않는다. 메타데이터 읽기는 해당 규칙을 켠 항목으로 제한하고 전체 파일 읽기·영상 프레임 decode·cloud 다운로드를 기본 실행하지 않는다. 값이 없으면 빈 이름을 적용하지 않고 미리보기에서 해결 또는 제외한다.
5. 기존 로컬 writable APFS 변경 범위와 symlink/alias/package/mount 보호를 유지한다. CSV와 규칙의 결과는 같은 부모 안의 leaf만 허용하며 slash, NUL, dot 항목, byte 길이 초과를 거부한다.
6. 이름 swap·cycle·case-only·중첩 폴더는 별도 계획 그래프로 처리한다. 전체 배치의 원자성을 주장하지 않는다. 중간 실패 시 항목별 상태와 복구 경로를 보존한다.
7. 현재 SOURCE_RACE는 실제 재현 결함이다. 재검사·flock·NSFileCoordinator만으로 비협조 외부 writer까지 막았다고 주장하지 않는다. P0에서 개선 가능 범위와 해결 불가능한 조건을 근거로 남긴다. 해결 없이 조용히 완료 처리하거나 위험 계약을 약화하지 않는다. 독립적인 모델·화면 개발은 계속할 수 있다.
8. 클립보드·파일 경로·텍스트·메타데이터는 기본 로그에 남기지 않는다. 진단 export는 기존 마스킹·명시 확인을 따른다. 무료·Pro 모두 로컬 처리이며 자동 파일 업로드와 서비스 계정은 필요하지 않다.
9. 폴더 감시는 새 항목을 찾아 대기열을 만드는 기능이다. 발견 즉시 이름을 바꾸지 않는다. 권한 철회·볼륨 분리·overflow·sleep/wake를 드러내고 재검사한다.
10. 기존 카드와 정보의 의미를 보존하고 Pro 도구 영역은 접을 수 있게 한다. 좁은 창에서 정보가 삭제되지 않도록 스크롤/재배치한다. 기본 Olive, 네 테마, ko/en/ja를 모든 새 화면에 적용한다.

## 구조와 데이터 모델

현재 UI → Application → Core/Infrastructure 경계를 유지한다. 아래 타입과 파일 이름은 새 설계 제안이며 존재하는 구현이라고 가정하지 않는다.

| 계층 | 추가 책임 | 주 변경 위치 |
|---|---|---|
| Core | NormalizationTarget, RenameRule, RulePipeline, 순번·문자·CSV 매핑 순수 모델, capability ID | Packages/NameFixCore/Sources/NameFixCore |
| Application | PreviewSession, generation·입력 순서·규칙 snapshot, plan graph, 권한 검증, 모든 입력의 실행 조정 | Application/Planning.swift 및 새 서비스 |
| Infrastructure | 기존 FS·journal 확장, MetadataProvider, PresetStore, EntitlementProvider, WatchService, 제한된 regex worker | Infrastructure |
| App | 검사/규칙 작업영역, 단계별 미리보기, 텍스트 도구, 메뉴바, 설정·권한·감시 상태 | App/MainView.swift, Sheets.swift, Main.swift 및 새 뷰 |
| CLI | 구조화 출력·종료 코드, plan·확인 UI 전달; 공유 Application 사용 | 별도 executable target 신설 |

기존 FileEntry.status.fixable은 NFC 전용 가정이 있으므로 범용 rename 적격성과 분리한다. 정규화 상태가 정상인 파일도 무료/Pro 이름 변경 규칙의 대상이 될 수 있어야 한다. rename 목적지에는 최종 raw leaf를 저장하고 규칙 재실행으로 Undo 이름을 재계산하지 않는다.

규칙과 프리셋은 schemaVersion, stable rule ID, 파라미터, 적용 범위, 순서·locale·timezone 정책을 저장한다. 가져온 데이터는 실행 코드가 아닌 허용된 규칙 데이터만 허용한다. 알 수 없는 schema/규칙을 조용히 생략하여 실행하지 않고 원본 보존·읽기 전용 오류를 제공한다. 기존 settings/journal은 fixture를 통해 업그레이드 전후 호환을 확인한다.

정규식은 취소와 실행 예산을 갖는다. Swift Task 취소만으로 동기 regex가 중단된다고 가정하지 않는다. 시간 제한을 보장할 수 없는 엔진은 종료 가능한 worker 격리나 지원 문법 제한으로 해결하며 병적인 패턴으로 검증한다.

## 단계별 구현과 완료 기준

단계 번호는 기존 Master Phase와 구분되는 확장 P0~P9이다. 각 단계는 관련 기능이 실제 동작하고 좁은 범위의 검증을 통과해야 완료한다. 아래 기준은 목표이며 PASS 기록이 아니다.

### P0 기존 계약과 실행 모델 정비

- 현재 source·도구·Debug 기준선을 기록하고 SOURCE_RACE의 실제 fixture와 보호 동작을 확인한다. 영향 없는 전체 검증을 반복하지 않는다.
- NFC 전용 적격성을 분리하고 UI·CLI·감시가 공유할 plan/application 경계를 만든다.
- FeatureCapability와 EntitlementProvider 경계를 정의한다. 무료/Pro/권한 불명/취소 상태를 테스트 공급자로 검증하되 테스트 공급자를 판매용 권한으로 취급하지 않는다.
- 기존 journal·settings migration fixture와 변경 전 사용자 데이터 보존 정책을 고정한다.
- 완료 기준: 기존 NFC rename/undo가 퇴행하지 않고 새 모드가 기존 데이터와 공존. SOURCE_RACE 결과는 해결 또는 BLOCKED_CONTRACT로 별도 기록하며 다른 작업을 막지 않는다.

### P1 무료 Unicode와 텍스트 완성

- NFC/NFD 선택, 목표에 따른 후보·선택·도움말·확인 문구, 실제 APFS raw spelling 검증과 Undo.
- 기존 문자 구성 시각화 유지. 한글·가나·라틴 결합문자·emoji·혼합형·invalid UTF-8·정규화 불변 문자를 처리한다.
- 텍스트 입력·명시 붙여넣기·NFC/NFD 결과 복사. 기존 4096 UTF-16 보호 한계를 알리고 잘린 데이터를 전체 변환이라고 표시하지 않는다.
- 완료 기준: 양방향 실제 파일 fixture, 목표 변경 시 stale Plan 무효화, clipboard 분석과 파일 mutation 분리, 3언어 리소스. NFC→NFD가 실제 raw bytes를 바꿨다는 증거가 있어야 한다.

### P2 무료 Mac 접근성과 편의 기능

- 기존 Finder Services를 재사용하며 메뉴 노출·설정 안내를 보완한다. 필요 이상의 Finder 확장을 새로 만들지 않는다.
- 메뉴바에서 드롭·검사 열기·최근 폴더·진행 상태·종료를 제공하고 기존 주 창과 같은 모델을 사용한다.
- 선택적 Mac 로그인 시 실행은 기본 off. 서비스 가입을 뜻하지 않는 문구를 쓴다. OS 설정의 거부·해제 상태를 반영한다.
- 완료 알림은 앱이 비활성일 때 유용한 결과 중심으로 제공하고 권한 거부 시 앱 내부 결과를 유지한다.
- 완료 기준: 중복 입력·busy·창 닫기/다시 열기·종료/취소 관련 모델·통합 검증. 실제 OS 동작 미확인은 별도로 표시하되 결함으로 꾸미지 않는다.

### P3 무료 기본 규칙과 Pro 고급 규칙

- 무료 기본 규칙과 Pro 옵션의 경계는 제공 표를 적용한다. literal/와일드카드/정규식 치환, 접두·접미·위치 삽입, 앞뒤 삭제·유지, 공백 정리, 대소문자, 명시적 악센트 제거, 사용자 지정 이름, 확장자 편집을 구현한다.
- 문자 위치는 기본 grapheme 기준이다. 확장자는 기본 보호하고 숨김 파일·확장자 없는 파일·복합 확장자 규칙을 설명한다. 악센트 제거는 NFC와 별도이며 자동 적용하지 않는다.
- 일반 순번은 시작·양/음 증분·자릿수·폴더별 재시작·반복/주기 설정을 제공한다. 입력 순서/사용자 순서/정렬 snapshot을 고정하여 화면 필터 변경이 번호를 몰래 바꾸지 않게 한다.
- 대상 간 swap/cycle을 포함한 계획 그래프와 temp 예약, 부분 완료·Undo·Recovery를 확장한다. 외부 점유 파일에는 no-overwrite를 유지한다.
- 완료 기준: 순수 규칙 tests, 병적인 regex의 제한, cycle/중첩/외부 충돌/취소/journal gap의 전용 임시 fixture와 내용 hash 불변. 스캔 상태가 normal인 파일도 규칙으로 변경 가능해야 한다.

### P4 규칙 편집기와 프리셋

- 무료 규칙끼리의 조합과 재정렬에는 단계 수 제한이나 결제를 요구하지 않는다. 규칙 추가·제거·활성/비활성·재정렬·파일 조건, 단계별 전후 비교·변경 강조, 최종 충돌과 제외 이유를 제공한다.
- 무료 기본 제공 예제와 마지막 무료 규칙 설정 복원을 제공한다. Pro에는 사용자 프리셋 생성·복제·이름 변경·저장·가져오기·내보내기와 업무 예제를 제공한다. 잠긴 Pro 작업이 선택된 상태에서는 실행 전에 이유를 보여 준다.
- Pro에서 Free로 바뀌면 기존 프리셋 열람·보존·내보내기는 허용하고 새로운 Pro 실행만 제한한다. 기존 작업 Undo는 계속 제공한다.
- 완료 기준: 규칙 수정/선택 변경 중 늦은 preview 폐기, 프리셋 저장 실패·손상·새 schema 보존, 작은 창·긴 번역·키보드 사용 경로 검증.

### P5 CSV와 작업 목록

- UTF-8 BOM 포함 CSV/TSV 가져오기, 구분자·헤더·열 매핑 선택, 따옴표/개행 처리와 행별 오류를 제공한다. 해석할 수 없는 인코딩은 임의 추정으로 적용하지 않는다.
- 이름 매핑은 현재 이름 또는 선택 루트 기준 상대 경로를 명시한다. 중복 키·일치 없음·한 파일에 복수 매핑·정규화 동등 이름·대소문자 모호성은 확인 전 차단한다.
- 결과 이름은 leaf만 허용한다. 원시 이름이 다른 항목을 표시 문자열만으로 합치지 않는다.
- 사용자 요청 시 이전/이후 이름·상태·이유를 export한다. spreadsheet 수식으로 해석될 값은 안전한 표시용 내보내기를 기본으로 하며 재가져오기에서 값이 변하지 않도록 형식 정책을 구분한다.
- 완료 기준: CSV escaping·중복·모호성·경로 탈출·대형 취소·결과 round-trip tests. 파일 내용과 원본 목록 파일은 수정하지 않는다.

### P6 메타데이터와 파일 쌍

- 읽기 전용 필드 provider를 만든다. 1차 지원은 파일 생성/수정 시각·크기, 사진 EXIF 촬영시각/카메라, 음악 제목/아티스트/앨범/트랙, 영상 생성시각/길이, Spotlight 문서 제목/작성자이다.
- 지원 형식은 JPEG/TIFF/HEIC 이미지, MP3/M4A 음악, MOV/MP4 영상, PDF 문서부터 명시적으로 검증한다. 필드 부재·Spotlight 미색인·오프라인 파일·권한 부족은 지원 여부와 값 부재를 구분한다. 모든 RAW·음악 코덱을 지원한다고 쓰지 않는다.
- 사용자 날짜 포맷, 원본/선택 timezone, 같은 초의 순번, 필드 없는 항목의 제외/명시 fallback을 제공한다. preview와 실행에서 같은 metadata snapshot을 쓰며 source 변경 시 재확인한다.
- 동일 부모와 기본 이름을 갖는 RAW/JPEG/XMP 등은 후보 그룹을 보여주고 사용자가 묶음을 확인한다. RAW 파일 쌍 처리는 RAW 메타데이터 decode 지원과 구분한다. 불완전 그룹을 전체 성공으로 표시하지 않는다.
- 완료 기준: 직접 만든/사용 허용된 작은 fixture의 기대 필드·timezone·누락·권한 tests, 내용·메타데이터 불변, 메타데이터 규칙을 끈 기본 검사의 읽기 횟수 0.

### P7 폴더 감시와 CLI 작업 연계

- Pro 폴더 감시는 opt-in, 기본 off이며 보존되는 권한과 접근 상태를 표시한다. 이벤트 병합·자체 작업 제외·중복 제거·진행 중 쓰기 항목 대기·overflow 재검사를 구현한다.
- 대기열에서 프리셋을 적용해 preview를 만들고 사용자가 승인한 snapshot만 실행한다. 새로 유입된 항목은 기존 승인에 포함시키지 않는다. 일시정지·재개·폴더 제거·앱 종료 시 동작을 명시한다.
- CLI 기본 동작은 검사/dry-run이다. 실행은 확인 화면으로 전달하거나 대화형 최종 요약 확인을 사용한다. 무인 watch의 무확인 mutation과 임의 --force는 제공하지 않는다.
- Free CLI는 Unicode와 무료 기본 규칙 및 조합을 지원한다. Pro CLI는 정규식·고급 옵션·프리셋/CSV/메타데이터 capability를 같은 Application 계층에서 검사한다. 구조화 출력·취소·종료 코드·단일 process lock을 공유한다.
- 완료 기준: 중복 이벤트·overflow·재시작·권한 철회·mount 변화·GUI/CLI 동시 실행·Free 우회 방지·source 변동 재검증. 자동 발견과 자동 변경을 도움말에서 구분한다.

### P8 글로벌 사용성 및 성능 보완

- ko/en/ja 전체 새 키, 자연스러운 오류·도움말·Free/Pro 설명, 영어 파일 작업 예제, 키보드·VoiceOver·대비·초점 복원을 보완한다.
- Olive/System/Dark/Light, 좁은/넓은/낮은 창, 긴 이름·긴 번역, 기존 카드/Inspector/기록 보존을 확인한다. 미확인을 실제 결함과 구분한다.
- 최초 실행은 화면 크기 기반 기존 정책을 유지하며 Pro 패널을 켜도 저장한 창 크기를 덮어쓰지 않는다.
- 입력에 대한 작업 표시 목표 100ms 이내, 10k 항목 단순 규칙 preview 목표 p95 300ms 이내, 취소 요청 후 UI 표시 목표 100ms 이내로 측정한다. worker 중단 목표 1초 이내이며 안전 mutation 진행 중에는 항목 경계까지 기다린다. 목표 미달은 원인과 측정 범위를 기록한다.
- 1k/10k/100k 이름 fixture와 긴 이름·깊은 트리·한 폴더 집중, 10k metadata fixture를 구분한다. 검색/스크롤 latency·메모리 peak·idle CPU·파일 읽기 수·preview와 실행 시간을 따로 기록한다. 기본 이름 검사 성능은 같은 머신의 변경 전 Debug 기준선 대비 20% 초과 회귀 시 조사한다.
- 경쟁 앱 비교는 합법적으로 이용 가능한 설치본에 한해 같은 Mac·볼륨·데이터·정렬·작업으로 cold/warm을 분리하고 5회 측정한다. 평가판 제한/부재는 NOT_AVAILABLE로 남기고 제품 결함으로 분류하지 않는다. 기존 100k scan 수치는 GUI나 metadata 성능의 증거가 아니다.
- 무료 사용자 유입 정책의 탐색 사용성 평가를 진행 가능한 범위에서 기록한다. 참여자 모집·외부 연락은 사용자 지시 없이 실행하지 않는다. 참여 평가 대기는 구현 완료와 분리한다.
- 완료 기준: 실제 발견한 성능·표시 결함 수정, 관련 회귀 확인, 측정 데이터와 미측정 조건을 분리한 보고서.

### P9 무료와 Pro 통합 완료 판정

- 권한 확인을 UI·Application·CLI·감시·프리셋 모든 경로에 적용한다. 무료 기본 조합·일반 순번·결과 export에 paywall이 없고, 같은 규칙을 CLI로 전달해도 결과와 권한이 같음을 검증한다. Pro 규칙을 무료 규칙으로 조용히 누락하지 않고 실행 전에 제한 이유를 표시한다. 네트워크 오류·권한 철회·재실행·진행 중 권한 변경을 테스트한다.
- 실제 구매 공급자 adapter는 판매 채널·상품 식별자·키가 결정되면 연결한다. 개발용 Free/Pro 시뮬레이터는 Debug에서만 사용하며 배포 빌드에 강제 해제 스위치가 들어가지 않게 한다. 상점 연결이 없으면 PAID_PROVIDER_PENDING을 명시한다.
- 확장 필수 범위의 핵심 TODO/stub와 자동 수정 가능한 결함을 없앤 뒤 통합 Debug 검증을 한 번 수행한다. 실패 수정 후 해당 실패와 영향 회귀만 반복한다.
- 기능·성능·UX·디자인·안정성 다섯 영역으로 다시 판정한다. 실제 결함은 위치·근거·수정 계획을 기록하고 남지 않을 때까지 보완한다. SOURCE_RACE가 남으면 앱 자체 완성을 선언하지 않는다.
- 완료 기준: 작업 목록과 실제 소스·검증·Debug 앱 일치, Free/Pro 기능 접근 근거, 남은 외부 조건 분리. 판매 권한 mock 통과를 실제 결제 성공으로 보고하지 않는다.

## 검증 비용과 완료 상태

각 작업은 변경 target과 관련 unit/fixture/integration만 수행한다. 문서만 바뀌면 링크·범위·표의 일관성을 확인한다. 기존 eng/test.sh는 --level 숫자만으로 범위를 좁히지 않으므로 --scope 또는 정확한 XCTest filter를 지정한다. 새 suite가 생기면 이름을 실제 확인한 후 명령을 기록한다.

검증 상태는 NOT_RUN, PASS, FAIL, FLAKY_TEST, NOT_AVAILABLE을 사용한다. 구현 상태는 TODO, IN_PROGRESS, DONE, BLOCKED_CONTRACT, BLOCKED_EXTERNAL이다. DONE에는 코드·관련 compile/test·오류 경로·번역·문서·근거 경로가 필요하다. 외부 조건이 없어 검증하지 못한 기능은 DONE으로 바꾸지 않는다.

기존 .ai/validation-cache.json 형식을 유지하고 실제 source/test/dependency/toolchain/environment fingerprint를 사용한다. Core FS 변경은 scanner/executor/undo/recovery 검증에 영향을 전파한다. 문서 작성만으로 기존 코드 PASS를 무효화하거나 신규 PASS를 만들지 않는다.

단계 완료 때 관련 Debug 앱과 해당 단계 tests를 확인한다. 확장 전체가 연결되기 전 clean/full/패키지 검증을 반복하지 않는다. 사용자 승인 없이 commit/push, 사용자 실제 자료 일괄 변경, 앱 설정 강제 변경, Release/ZIP/DMG/서명 작업을 수행하지 않는다.

## 개발 산출물과 재개 방법

- EXPANSION_TASKS.md: ID·선행 조건·상태·직접 검증·근거·다음 작업.
- PROJECT_STATUS.md: 현재 작업, 완료 범위, 실제 Debug 앱 경로, 다음 미완료 항목.
- ARCHITECTURE.md: 구현된 구조만 갱신. 계획을 현재 구현으로 표현하지 않는다.
- FILESYSTEM_CAPABILITIES.md와 KNOWN_LIMITATIONS.md: 실제 입증한 보장과 한계.
- COMMERCIAL_REVIEW.md: 확장 범위의 다섯 영역 재판정. 과거 기준선과 날짜를 구분.
- .ai/validation-cache.json, artifacts/development/expansion/: 실제 실행 명령·환경·결과·fixture와 Debug 산출물 hash.
- 단계별 종료나 세션 전환 때 현재 ID, 변경 파일, 실행 결과, blocker와 독립적으로 할 다음 ID를 기록한다. 문서만 읽고 계획을 다시 만드는 것으로 구현을 대신하지 않는다.

가격·판매 채널·유료 라이선스 정책·상품 ID는 미결정이다. 공급자 결정이 없어도 기능 권한·상태 처리·전체 Free/Pro 앱 개발을 진행한다. AI/OCR/RAG, 웹판, 원격 서버 작업, cross-volume 이동, 압축 내부 이름 변경, 자동 NFKC/NFKD는 이번 범위 밖이다.

별도 단계: 출시 QA·스모크·서명·공증·앱스토어 심사·배포 준비·실제 판매 연결은 앱 자체 개발 판정과 구분하고 사용자 요청에 따라 진행한다.
